## Intencja

Jedno miejsce na Discordzie, z którego członek społeczności:

- widzi, co jest aktywne na serwerze;
- tworzy aktywność (jeśli ma uprawnienie);
- dołącza, rezygnuje, odpowiada;
- zarządza **własnymi** aktywnościami;
- dostaje czytelny feedback bez spamu na kanale.

WWW i Desktop Companion mają w przyszłości korzystać z **tych samych** reguł
i danych (Project Charter), ale P4 v1 kanałów = decyzja P4-D4.

## Zasady już obowiązujące (nie do renegocjacji w P4 bez nowego DEC)

1. Discord jest pełnoprawnym interfejsem (P3-D3).
2. Zwykłe aktywności nie wymagają logowania WWW (P3-D3).
3. Uprawnienia przez IDs V2, nie nazwy ról Discord (P3-D4).
4. Historia nie znika po leave/block (P3-D12/D16).
5. Stały panel + native components; funkcjonalność > dekoracja (D-023/D-024).

## Candidate capabilities (z P3-D3 — nie = zakres v1)

Lista referencyjna do wyboru w P4-D1/D2:

| Capability                      | Opis skrótowy                                |
| ------------------------------- | -------------------------------------------- |
| Hub / nawigacja                 | Stały panel wejściowy z menu kategorii/akcji |
| Tworzenie aktywności            | Nowy rekord w scope guild                    |
| Dołączanie / rezygnacja         | Uczestnictwo                                 |
| Wezwania / odpowiedzi           | Call-and-response (np. wsparcie)             |
| Wydarzenia własne               | Zarządzanie eventem autora                   |
| Rezerwacje                      | Zajęcie/zwolnienie slotu                     |
| Głosowanie                      | Proste ankiety                               |
| Preferencje powiadomień Discord | Lokalne ustawienia użytkownika               |

**v1 musi być świadomie wąski.** Rekomendacja techniczna: hub + dokładnie jeden
typ z powyższej listy (P4-D1 wariant A/B).

## Poza produktem P4

- pełna moderacja / tickety / analityka;
- automatyzacje wielokrokowe;
- integracje z grami / overlay desktop;
- publiczny SaaS multi-tenant.
